- `short_name`: the final fallback `first[: n - 1] + "…"` adds an ellipsis even when nothing was cut. If `len(first)` is `n - 2` or `n - 1` (e.g. `"Christophe Smith"` gives `"Christophe…"`), the whole first name fits. Return `first` unchanged when `len(first) <= n`, and truncate only when it is longer.
- `short_name`: there is no guard on `n`. With `n <= 0`, `name[: n - 1]` uses a negative index and returns nearly the whole string plus `"…"` (e.g. `n=0` gives `name[:-1] + "…"`), so the result is longer than `n`. Assert or clamp `n >= 1`.
- `short_name`: whitespace handling is inconsistent. A name within the limit is returned as-is (internal runs of spaces kept), but longer names are rebuilt from `split()` and normalized. Pick one behavior.
- `short_name`: `len()` counts code points, not displayed characters. Names with combining marks or wide CJK characters can exceed or fall short of the intended visual width. Fine if code points are what's intended, but document it.
- No tests were added for `short_name`. It has several branches (fits as-is, single long word, "First L." form, long-first-name fallback) and boundary cases at exactly `n` and `n - 1` that should be covered.
