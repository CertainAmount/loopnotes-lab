- Connection leak: the `if not rows: return 0` path returns without calling `conn.close()`, so every empty-month export leaks a SQLite connection and file handle.
- Connection leak on errors: if `execute`, `fetchall`, or `write_rows` raises, `conn.close()` never runs. Wrap the connection in `try/finally` or `contextlib.closing(sqlite3.connect(...))`. Note that `with sqlite3.connect(...)` alone manages transactions and does not close the connection.
- Memory usage: `fetchall()` loads the whole month's result set into memory. Large months can exhaust memory. Iterate the cursor (or use `fetchmany`) and stream rows into `write_rows`, which already accepts any iterable.
- Data integrity: when there are no rows, `out_path` is left untouched, so a stale file from a previous run stays in place and looks like a valid export for this month. Either write an empty (header-only) file or remove or flag the old one.
- Data integrity: if `write_rows` fails partway (disk full, I/O error, exception mid-iteration), a truncated CSV is left at `out_path` with no indication it is incomplete. Write to a temp file in the same directory and `os.replace` it into place only on success.
- Security: if `out_path` (or `db_path`) can come from user input, nothing restricts it to an export directory, which allows arbitrary file overwrite or path traversal. Validate or resolve it against an allowed base directory.
