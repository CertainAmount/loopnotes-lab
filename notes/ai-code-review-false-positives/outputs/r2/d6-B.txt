- `short_name`: when `first` is 10 or 11 characters long (with n=12), `first[: n - 1] + "…"` keeps all of `first` and still adds "…". The result suggests truncation that didn't happen (e.g. "Christophe Zimmermann" → "Christophe…"). Return `first` unchanged when `len(first) <= n`, and only truncate and add the ellipsis when it is longer.
- `short_name`: the multi-word fallback drops the last-name initial entirely, so "Christophe Zimmermann" and "Christophe Abel" both become "Christophe…". If telling people apart matters, consider truncating `first` enough to keep the `L.` suffix.
- `short_name`: there is no guard on `n`. With `n <= 0`, `name[: n - 1]` uses a negative slice and returns most of the string rather than a short one. With `n < 3`, every output is longer than `n`. Assert `n >= 1`, or document the minimum.
- `short_name`: the length checks count code points, not graphemes or display width. Combining marks, emoji ZWJ sequences, and CJK full-width names can still overflow the visual budget, and `last[0]` or the slice can split a grapheme cluster (e.g. leave a dangling combining accent).
- `short_name`: no tests were added. Cover the boundary cases: exactly `n` chars, a single long word, `first last` that fits, `first last` that doesn't, a first name of length `n-2`/`n-1`/`n`, and non-ASCII input.
