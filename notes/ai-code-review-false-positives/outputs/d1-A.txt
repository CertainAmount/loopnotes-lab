- `get_team_badge` doesn't handle `repo.find_by_id(uid)` returning `None`, so `user.team_id` raises `AttributeError`; `get_display_name` just above guards this case and returns "Unknown user".
- `repo.find_team(user.team_id)` isn't checked for `None` either, so a user with no team (`team_id` is `None`) or a deleted team crashes on `team.short_label`.
- `get_team_badges` makes two repository queries per uid, an N+1 pattern; batch-fetch users and teams (e.g. `find_by_ids` / `find_teams`) instead.
- Duplicate or shared team IDs in `get_team_badges` cause the same team to be fetched again; cache or dedupe team lookups at least.
- One missing user or team in `get_team_badges` makes the whole batch fail; decide whether to skip, use a placeholder, or raise, and document it.
- `get_team_badges` can be a list comprehension: `return [get_team_badge(u) for u in uids]`.
- `short_label or name` falls back silently when `short_label` is an empty string, and still produces `"Name · None"` if both are empty or `None`; add an explicit fallback.
- The separator `" · "` is hard-coded in the service layer; badge formatting belongs in the presentation layer or a shared constant, especially if it needs to be localized.
- No tests cover the new functions, including the missing user/team and empty-`short_label` cases.
